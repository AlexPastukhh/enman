# Тема: Реализация сценариев приложения через slices

**Статус:** быстрый topic-драфт v1 / глава 3 / самый важный файл для преддипломной / нужен repo-check по фактическим slices, endpoints, handlers, UI routes, tests и demo flow.

1. Зачем тема нужна

Эта тема показывает, какие пользовательские сценарии реально реализованы в приложении.

Главная мысль:

Реализация приложения может быть описана через вертикальные slices: каждый slice закрывает конкретный пользовательский сценарий от UI и API до application/domain logic и хранения данных. Такой подход удобен для преддипломной, потому что позволяет быстро показать, что система не только спроектирована, но и работает по ключевой цепочке: заявка → рассмотрение → решение → договорный обмен → файл.

2. Что такое slice в этой главе

В этой главе slice — это не обязательно отдельная папка в коде. Это реализованный вертикальный сценарий.

Для каждого slice фиксируем:

1. Пользовательское действие.
2. Роль: клиент или сотрудник.
3. UI-экран.
4. API endpoint / handler.
5. Application/domain logic.
6. Хранение результата.
7. Тест или demo-проверка.

Тезис:

Slice показывает реализацию сценария целиком: от действия пользователя в интерфейсе до изменения состояния в backend и сохранения результата.

- frontend отправляет command;
- backend создаёт заявку;

Текст:

Slice создания заявки показывает основной клиентский сценарий. Frontend собирает данные формы, но не задаёт статус заявки напрямую. Backend создаёт заявку, связывает её с заявителем и сохраняет начальное состояние процесса.

9. Slice: начало рассмотрения

Flow:

→ нажимает “Начать рассмотрение”
→ backend проверяет роль и состояние
→ создаётся/обновляется review state
→ UI обновляется

Текст:

Slice начала рассмотрения показывает сценарную природу command API. Frontend не меняет статус напрямую, а запускает команду, после которой backend проверяет допустимость перехода.

10. Slice: проверка данных

Flow:

сотрудник запускает проверку
→ backend выполняет mock/check operation
→ результат отображается в карточке
→ решение всё равно принимает сотрудник

Текст:

Проверка данных реализуется как вспомогательный slice. Она помогает сотруднику принять решение, но не заменяет approve/reject и не меняет итог заявки автоматически.

Repo-check:

- где хранится результат;
- как результат показывается в UI;
- tests/mock service.

16. Slice: получение файла

Flow:

frontend запрашивает documentId
→ backend находит metadata
→ проверяет access через proposal/exchange/request

Текст:

Slice получения файла показывает, что договорные документы не раздаются как public static files. Backend проверяет доступ и только после этого возвращает physical file.

Repo-check:

- access check;

20. Черновой текст

Реализация приложения может быть описана через набор вертикальных slices, каждый из которых соответствует пользовательскому сценарию. Такой slice включает frontend-экран, API-операцию, application/domain logic и сохранение результата.

Основная цепочка реализации начинается с создания заявителя и заявки клиентом. После этого сотрудник видит заявку в рабочем списке, открывает карточку, начинает рассмотрение, выполняет проверку данных и принимает решение. При одобрении заявки становится доступен договорный обмен, в рамках которого стороны могут отправлять версии договорного предложения и работать с прикреплёнными файлами.

Такой подход удобен для проверки реализации, потому что каждый slice можно отдельно продемонстрировать и протестировать. Например, slice одобрения заявки включает кнопку в интерфейсе сотрудника, command API, проверку состояния заявки в domain layer и сохранение решения в БД.
