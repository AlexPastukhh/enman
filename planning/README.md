# Planning

`planning/` — живая память проекта для AI-агентов и разработчика.

Цель каталога:
- сохранить контекст между сессиями;
- уменьшить расход токенов;
- не возвращаться к уже принятым архитектурным спорам;
- фиксировать принятые решения, выполненные действия и риски;
- помогать агенту выполнять маленькие безопасные задачи без потери общей картины.

## Быстрый порядок чтения

### Всегда читать перед работой

1. `current-state.md`
2. `agent-rules.md`

### Читать по задаче

| Тип задачи | Что читать |
|---|---|
| Домен / классы | `domain-model.md`, `decisions.md`, `layer-plan.md` |
| API / контроллеры / DTO | `api-plan.md`, `use-cases.md`, `decisions.md` |
| Тесты | `testing-strategy.md`, `current-state.md` |
| Архитектура / рефакторинг | `layer-plan.md`, `decisions.md`, `risk-log.md`, `solution-map-and-cleanup-plan.md` |
| Документация диплома | `general-project-info.md`, `use-cases.md`, `layer-plan.md` |
| Cleanup / структура solution | `solution-map-and-cleanup-plan.md`, `action-log.md`, `risk-log.md` |

## Source of truth

Если код и planning расходятся, агент обязан:

1. явно указать расхождение;
2. предложить безопасные варианты;
3. не менять архитектуру молча;
4. после принятия решения обновить planning.

## Правило обновления

После каждого значимого изменения:

- обновить `current-state.md`;
- добавить запись в `action-log.md`;
- обновить `decisions.md`, если принято новое решение;
- обновить `risk-log.md`, если появился риск;
- обновить профильный файл: `domain-model.md`, `api-plan.md`, `testing-strategy.md` или `layer-plan.md`.

## Что считать значимым изменением

- добавлен/переименован класс;
- изменен endpoint;
- изменена EF mapping strategy;
- добавлен/удален слой функционала;
- изменена тестовая стратегия;
- удалены или перемещены файлы;
- изменен способ генерации контрактов;
- обнаружен риск или конфликт между planning и кодом.

## Важное правило по старым планам

Старые планы не должны оставаться активными рядом с актуальными. Их нужно:

- перенести в `archive/`;
- пометить как deprecated;
- кратко объяснить, почему они устарели.

Git уже хранит историю изменений, поэтому не нужно плодить много копий planning-файлов.
