# 0. Краткий source-pass

По проектным файлам видно, что серверная часть реализуется на **.NET 8 / ASP.NET Core**. В серверном проекте используются Entity Framework Core, Dapper, FluentValidation, MediatR, Serilog, Swashbuckle/OpenAPI и Docker-настройки. Также указан `SpaProxy`, связывающий серверную часть с клиентским приложением. 

Клиентская часть использует **React**, **TypeScript**, **Vite**, React Router, TanStack React Query, React Hook Form, Zod, Vitest, Testing Library, Playwright и генерацию типов API через `openapi-typescript`. 

Для серверного тестирования используются xUnit, FluentAssertions, Moq, Microsoft.AspNetCore.Mvc.Testing и coverlet. 

Для локальной разработки важны конкретные настройки запуска: сервер ASP.NET Core имеет профили `http`, `https`, `IIS Express` и `Container (Dockerfile)`. В режиме разработки сервер запускается на `http://localhost:5156` и `https://localhost:7250`, а контейнерный профиль использует порты `8080` и `8081`. 

Клиентская часть Vite запускается на `https://localhost:5173`, использует локальные сертификаты и проксирует запросы `/api` на `https://localhost:7250`. Это значит, что в локальной среде frontend и backend работают как отдельные процессы, но запросы к API направляются на серверную часть. 

Dockerfile серверной части выполняет восстановление зависимостей, сборку, публикацию ASP.NET Core приложения и запуск опубликованного приложения в контейнере.

# 8. Clean text candidate

## 2.8 Средства выполнения ВКР

Для выполнения ВКР необходимо определить набор средств, обеспечивающих проектирование, разработку, запуск и проверку web-приложения. Эти средства можно разделить на аппаратные, программные, информационные, сетевые и организационные. Такое разделение позволяет показать, за счёт каких ресурсов выполняется разработка системы и обеспечивается её работоспособность.

К аппаратным средствам относятся рабочая станция разработчика, серверная среда для запуска приложения и пользовательские устройства. Рабочая станция разработчика должна обеспечивать запуск среды разработки, серверной части, клиентской части, базы данных и средств тестирования. Пользовательское устройство должно иметь современный web-браузер для работы с интерфейсом приложения.

Программные средства включают инструменты и технологии, используемые для реализации приложения. Серверная часть web-приложения разрабатывается на платформе .NET 8 с использованием ASP.NET Core. Для работы с данными используются Entity Framework Core и Dapper, для проверки входных данных — FluentValidation, для организации прикладных сценариев — MediatR, для логирования — Serilog. Для описания API используется OpenAPI/Swagger. Клиентская часть реализуется с использованием React, TypeScript и Vite. Для маршрутизации, работы с серверными данными и формами используются React Router, TanStack React Query, React Hook Form и Zod. Для тестирования применяются xUnit, Vitest, Testing Library и Playwright.

Для разработки используется локальная схема запуска, при которой серверная и клиентская части работают как отдельные процессы на `localhost`. Серверная часть ASP.NET Core запускается на локальных HTTP/HTTPS-адресах, а клиентская часть Vite — на отдельном HTTPS-порту. Запросы клиентской части к `/api` проксируются на серверную часть. Такая схема удобна для разработки, потому что позволяет независимо запускать frontend и backend, сохраняя при этом поведение web-приложения как единой клиент-серверной системы.

Для контейнерного запуска предусмотрен Dockerfile серверной части. Он описывает восстановление зависимостей, сборку, публикацию и запуск ASP.NET Core приложения в контейнерной среде. В контейнерном профиле используются отдельные HTTP/HTTPS-порты. Поэтому контейнерный запуск можно рассматривать как средство воспроизводимого запуска серверной части, не смешивая его с описанием полноценной промышленной инфраструктуры эксплуатации.

Информационное обеспечение включает материалы, необходимые для проектирования и проверки системы. К ним относятся сценарии работы пользователей, требования к web-приложению, модель предметной области, структура хранения данных и документов, API-спецификация, диаграммы, тестовые данные, исходный код и проектная документация. Эти материалы позволяют связать требования, проектные решения и реализацию приложения.

Сетевое обеспечение определяется тем, что система является web-приложением. Пользователь работает с приложением через браузер, клиентская часть отправляет запросы к серверному API, серверная часть обрабатывает эти запросы, обращается к базе данных и возвращает результат. Для такого взаимодействия используется клиент-серверная схема обмена данными по HTTP/HTTPS.

В локальной среде разработки сетевое взаимодействие также строится по клиент-серверной схеме. Браузер обращается к клиентской части, запущенной через Vite, а запросы к API перенаправляются на сервер ASP.NET Core. Это позволяет сохранить реалистичную схему взаимодействия даже при локальной разработке: интерфейс работает отдельно, серверная часть обрабатывает API-запросы, а данные сохраняются в базе данных или связанном хранилище.

Организационное обеспечение включает способы управления выполнением ВКР и изменениями проекта. К нему относятся ведение репозитория исходного кода, разделение работ по сценариям и функциональным частям, фиксация проектных решений, использование тестирования и подготовка документации. Эти меры позволяют сохранять связь между требованиями, проектированием и реализацией.
