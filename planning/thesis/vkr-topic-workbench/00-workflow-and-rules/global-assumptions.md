# Global assumptions and guardrails

## Clean VKR language

Do not mention AI, ChatGPT, prompts, chats, agents or generation workflow in VKR text.

## L1/L2

Do not use L1/L2 as thesis concepts. Use subject/engineering names instead.

## Account activation

Account activation is not a central implemented VKR user flow. If it appears in planning/repo, treat it as supporting auth detail or future/limited detail unless a separate repo-check proves otherwise.

## Mock data verification

Mock check is a demonstration / extension point. Do not call it real external verification.

## Agreement stage

Agreement stage starts after approval and is initiated by the employee. The system does not automatically generate a contract. It supports exchange of ready document versions.

## Document storage

Document reference / metadata is not a full ECM/EDO/file storage system. Do not claim e-signature, legal EDO, external integrations, industrial file storage or full file audit without repo-check.

## Email notifications

Do not claim full email notification implementation without repo/evidence check.
