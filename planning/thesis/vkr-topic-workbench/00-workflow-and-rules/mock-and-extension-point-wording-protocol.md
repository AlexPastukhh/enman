# Протокол описания mock/demo/stub-возможностей

Статус: актуально

## 1. Назначение

Этот протокол нужен, чтобы в ВКР можно было использовать демонстрационные элементы интерфейса без завышения статуса реализации.

Пример: кнопка проверки данных заявки сотрудником.

## 2. Разделять уровни

Для каждой такой возможности разделять:

```text
1. Что реально реализовано.
2. Что имитируется.
3. Какая точка расширения показана.
4. Что относится к дальнейшему развитию.
```

## 3. Пример для проверки данных

### Что реализовано

```text
кнопка проверки данных в интерфейсе сотрудника;
отображение демонстрационного результата проверки;
базовая проверка заполненности/формата, если она есть в коде;
```

### Что имитируется

```text
результат внешней проверки без обращения к внешнему сервису.
```

### Точка расширения

```text
место будущего подключения внешнего источника проверки данных.
```

### Дальнейшее развитие

```text
реальная интеграция с внешним API/реестром;
сохранение истории проверок;
расширенные правила верификации;
аудит результатов проверки.
```

## 4. Разрешённые формулировки

```text
демонстрационная проверка данных;
имитационная проверка;
mock-проверка;
заглушка внешней интеграции;
точка расширения для будущей внешней проверки;
```

## 5. Запрещённые или опасные формулировки

Не писать без реальной реализации:

```text
реализована внешняя проверка данных;
система проверяет данные по внешним реестрам;
система автоматически подтверждает достоверность данных;
выполнена интеграция с внешним сервисом;
```

## 6. Где упоминать

### Глава 1

Как потенциальный уровень автоматизации:

```text
процесс может предусматривать демонстрационную точку расширения для проверки данных.
```

### Глава 2

Как проектное решение в сценарии сотрудника:

```text
в сценарии рассмотрения заявки предусмотрено действие проверки данных.
```

### Глава 3

Как UI/implementation evidence:

```text
на странице сотрудника добавлена кнопка демонстрационной проверки данных, которая показывает место будущей интеграции.
```

### Заключение / дальнейшее развитие

```text
реальная внешняя верификация данных относится к дальнейшему развитию системы.
```
