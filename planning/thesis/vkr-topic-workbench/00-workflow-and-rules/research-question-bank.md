# Банк вопросов к research и к проекту

Статус: рабочий список

## 1. Назначение

Этот файл хранит типовые вопросы, которые можно использовать при подготовке topic-драфтов и генерации текста. Вопросы помогают не вставлять research буквально, а находить в нём ответы на потребности конкретной темы.

## 2. Вопросы к research для главы 1

### 1.1 Процесс обработки клиентской заявки

| Вопрос | Где искать | Как использовать |
|---|---|---|
| Почему заявка должна иметь статус и историю? | comparative research: service desk / request management | кратко, без теории; основа темы всё равно проектная |
| Почему личный кабинет лучше анонимного обращения для управляемого процесса? | comparative research: portal, roles, status | как поддержку логики аккаунта, не как юридическое требование |
| Почему email + Excel слабее специализированной системы? | comparative research: email + Excel baseline | лучше вынести в 1.3 |

### 1.2 Договорно-документный этап

| Вопрос | Где искать | Как использовать |

| Почему документ должен быть связан с процессом? | literature research: records management, workflow/BPM | после объяснения “заявка → решение → договорный этап” |

## 3. Вопросы для конкретизации проекта

Эти вопросы адресуются не research, а проекту, repo-check или обсуждениям.

| Вопрос | Зачем нужен |
|---|---|
| Что реально реализовано, а что только проектируется? | не завысить текст |
| Где в UI начинается договорный этап? | для скриншотов и главы 3 |
| Какие статусы есть у договорного обмена? | для диаграммы жизненного цикла |
| Сохраняется ли история всех версий? | для формулировок 1.2 и главы 3 |
| Какие уведомления реально есть? | для 1.2.3 |
| Что можно показывать скриншотом? | для визуального чата |
| Какие функции являются mock/demo/stub? | для границ утверждений |

## 4. Как использовать вопросы при генерации текста

```text
1. Взять карту будущего текста из topic-драфта.
2. Для каждого абзаца понять: нужен ли research?
3. Если нужен — выбрать вопрос из этого банка или сформулировать новый.
4. Найти ответ в research.
5. Переписать ответ под нашу тему.
6. Вставить коротко, без research dump.
```
