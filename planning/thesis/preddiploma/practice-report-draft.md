## Введение

Преддипломная практика выполнялась по теме ВКР, связанной с разработкой web-приложения для автоматизации обработки клиентских заявок и связанного документооборота в сетевой компании ООО «ЗСК».

Актуальность темы определяется тем, что процесс работы с клиентскими обращениями включает регистрацию клиента, указание заявителя, подачу заявки, рассмотрение сотрудником, фиксацию решения, подготовку договорного документа и обратную связь с клиентом.

Цель практики — подготовить и уточнить материалы ВКР, завершить проектирование основных компонентов web-приложения, выполнить разработку и проверку текущего программного среза, а также подготовить материалы к предзащите.

## 1 Выполненные работы по теме ВКР

### 1.1 Анализ предметной области

Ключевой процесс:

```text
клиент → заявитель → заявка → сотрудник → решение → договорный документ → уведомление / обратная связь
```

Клиентская заявка рассматривается как входная точка процесса и связывает клиентский аккаунт, заявителя, адрес объекта обслуживания, статус обработки и результат проверки.

### 1.2 Уточнение цели и задач ВКР

Цель ВКР:

```text
разработать web-приложение, которое обеспечивает подачу клиентских заявок,
их рассмотрение сотрудником, связь с договорно-документным этапом
и поддержку обратной связи с клиентом.
```

### 1.3 Подготовка проектных материалов

Подготовлены материалы по сценариям, требованиям, жизненному циклу заявки, жизненному циклу договорного обмена, доменной модели, БД, архитектуре, API и тестированию.

## 2 Проектирование и разработка web-приложения

### 2.1 Пользовательские сценарии

Для клиента: регистрация, вход, создание заявителя, подача заявки, просмотр заявок, участие в договорном обмене.

Для сотрудника: просмотр очереди, открытие заявки, начало рассмотрения, одобрение/отклонение, запуск договорного обмена.

### 2.2 Архитектура приложения

Система построена как web-приложение с ASP.NET Core backend и React/TypeScript frontend. Взаимодействие выполняется через REST API и OpenAPI-контракт.

### 2.3 Доменная модель и структура данных

Основные сущности: ClientAccount, ApplicantParty, ConnectionRequest, ReviewResult, Employee, AgreementProposalExchange, AgreementProposal, AgreementDocumentRef.

### 2.4 Договорно-документный обмен

В текущем срезе реализована модель agreement exchange, связывающая положительное решение по заявке с обменом версиями договорного документа.

Важно: система хранит ссылку на документ и его метаданные, но не является полноценным файловым хранилищем.

### 2.5 Реализованные элементы backend

Реализованы API-группы для регистрации/входа, заявителей, заявок клиента, заявок сотрудника, действий рассмотрения, договорного обмена, antiforgery и обработки ошибок.

### 2.6 Реализованные элементы frontend

Реализованы экраны регистрации, входа, аккаунта, создания заявки, списка заявок, деталей заявки, панели сотрудника, карточки заявки сотрудника, списка и деталей договорных обменов.
