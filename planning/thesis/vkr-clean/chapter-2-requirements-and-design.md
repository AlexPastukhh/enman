# Chapter 2. Requirements And Design

Status: draft

## 2.1. Общая характеристика проектируемой системы

Проектируемая система представляет собой web-приложение для автоматизации обработки клиентских заявок и документооборота в сетевой компании ООО «ЗСК». Система должна обеспечивать клиенту возможность регистрации, входа, создания заявителя и подачи заявки. Сотрудник должен иметь возможность видеть поступившие заявки, брать их в обработку, выполнять ручную проверку, одобрять или отклонять заявки.

После одобрения заявки система должна поддерживать создание проекта договора или связанного документа. Клиент должен получать уведомление о результате обработки или появлении документа.

## 2.2. Роли пользователей

В системе выделяются две основные роли:

- клиент;
- сотрудник сетевой компании.

Клиент работает с собственными данными, заявителями, заявками и документами. Сотрудник работает с очередью заявок, результатами проверки и договорными документами.

[IMPLEMENTED] Клиент может подать заявку, указав заявителя, описание и адрес объекта.

## 2.4. Нефункциональные требования

Система должна быть реализована как web-приложение с разделением frontend и backend. Backend должен предоставлять API для выполнения операций, а frontend должен обеспечивать удобный пользовательский интерфейс.

Данные должны храниться в базе данных. Для защиты данных необходимо предусмотреть аутентификацию пользователей и разграничение доступа к собственным заявкам и документам.

Система должна быть расширяемой, чтобы в дальнейшем можно было добавить новые типы заявителей, дополнительные статусы обработки, расширенный документооборот и интеграцию с внешними сервисами уведомлений.

## 2.5. Жизненный цикл заявки

Проектный жизненный цикл заявки включает следующие состояния:

1. Заявка создана клиентом.
2. Заявка ожидает обработки или находится на рассмотрении.
3. Сотрудник берет заявку в работу.
4. Сотрудник выполняет ручную проверку.
5. Заявка получает результат: одобрена или отклонена.
6. При одобрении может быть создан проект договора или документа.

В текущей реализации базового среза подтверждено создание заявки. Расширенный цикл обработки сотрудником относится к целевой версии системы.

## 2.6. Жизненный цикл проекта договора или документа

Проект договора создается только после одобрения заявки. Это обеспечивает связь между результатом рассмотрения заявки и дальнейшим документооборотом.

Базовый проектный процесс:

1. Сотрудник открывает одобренную заявку.
2. Сотрудник создает проект договора или связанного документа.
3. Документ связывается с заявкой и клиентом.
4. Клиент получает email-уведомление.
5. Клиент может перейти к просмотру документа.

## 2.7. Основные проектные ограничения

- Заявка должна быть связана с конкретным заявителем.
- Заявитель должен принадлежать клиентскому аккаунту.
- Клиент не должен иметь доступ к чужим заявкам.
- Сотрудник должен обрабатывать только существующие заявки.
- Проект договора не должен создаваться для отклоненной или необработанной заявки.
- Email-уведомление должно отправляться только после значимого события: одобрение, отклонение или создание документа.
