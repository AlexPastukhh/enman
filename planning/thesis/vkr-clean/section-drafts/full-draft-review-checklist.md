# Full Draft Review Checklist

Status: current checklist  
Scope: how to review full VKR subsection draft attempts

Use this checklist after creating a full draft attempt.

## 1. Project Connection

```text
[ ] Does the subsection answer its project question?
[ ] Is ООО «ЗСК» project context visible?
[ ] Are client, applicant, request, employee, decision, document or notification connected when relevant?
[ ] Does the subsection avoid generic theory not tied to the project?
```

## 2. Narrative Flow

```text
[ ] Does the text follow the short draft high-level flow?
[ ] Is the order of ideas natural?
[ ] Is there a clear transition to the previous/next subsection?
[ ] Are there places where the text jumps too quickly to implementation?
```

## 3. Research Usage

```text
[ ] Are external sources used only for facts, criteria, definitions or comparison?
[ ] Are there any research-like paragraphs that should be rewritten from project perspective?
[ ] Are product/vendor claims cited?
[ ] Are author conclusions clearly separated from external facts?
```

## 4. Implementation Claims

```text
[ ] Does every implementation claim need repo check?
[ ] Are unimplemented or partially implemented features presented carefully?
[ ] Are TODO CHECK REPO markers kept where status may change?
[ ] Are screenshots/tests/API artifacts required?
```

## 5. Visual / Table Support

```text
[ ] Would a diagram/table/screenshot explain this better than prose?
[ ] Are TODO INSERT markers placed?
[ ] Is each planned artifact connected to the text?
[ ] Should a large diagram go to appendix instead of main text?
```

## 6. Fragment Harvest

```text
[ ] Which paragraphs are especially strong?
[ ] Which transitions can be reused?
[ ] Which conclusions should be saved?
[ ] Which figure/table captions are good enough to keep?
[ ] Were saved fragments moved to fragment-bank.md?
```

## 7. Anti-Patterns

Check for:

```text
[ ] "In the modern digital world..." style opening.
[ ] Pure technology description without project need.
[ ] Long external product descriptions.
[ ] Repeated claims from another section.
[ ] Unclear status of implementation.
[ ] Missing citation for external fact.
[ ] Missing project reason for a general statement.
```

## 8. Outcome

Choose one:

```text
- continue to full-draft-v2;
- harvest fragments and rewrite;
- source-check;
- repo-check;
- prepare visuals;
- mark chapter-ready;
- supersede draft.
```
