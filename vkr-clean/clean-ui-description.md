# Clean UI Description

Status: draft

## Общая структура интерфейса

Пользовательский интерфейс web-приложения должен поддерживать два основных рабочих пространства:

- личный кабинет клиента;
- рабочее место сотрудника.

## Страницы клиента

### Регистрация

Клиент вводит email и пароль. После успешной регистрации создается учетная запись.

### Вход

Клиент вводит email и пароль и получает доступ к личному кабинету.

### Создание заявителя

Клиент вводит ФИО, email и телефон заявителя-физического лица.

### Создание заявки

Клиент выбирает заявителя, вводит описание заявки и адрес объекта.

### Мои заявки

Клиент видит список собственных заявок, их статусы и дату создания.

### Детали заявки

Клиент видит данные заявки, статус обработки, результат проверки и причину отклонения, если заявка отклонена.

### Документы

Клиент видит проекты договоров или документов, связанные с одобренными заявками.

## Страницы сотрудника

### Панель заявок

Сотрудник видит список заявок, может фильтровать их по статусу и открывать детали.

### Детали заявки

Сотрудник видит данные клиента, заявителя, адрес объекта и описание заявки.

### Проверка заявки

Сотрудник выполняет ручную проверку и выбирает решение: одобрить или отклонить.

### Создание проекта договора

После одобрения заявки сотрудник создает проект договора или документа и связывает его с заявкой.

## Состояния интерфейса

Интерфейс должен отображать:

- успешное создание аккаунта;
- ошибки входа;
- ошибки валидации формы;
- пустой список заявок;
- статус заявки;
- доступные действия для текущего статуса;
- успешное создание документа;
- факт отправки уведомления, если функция включена.
