# Definitions, Designations And Abbreviations

Status: draft  
Scope: candidate "Определения, обозначения и сокращения" section for the VKR

This file can be used as a base for the preliminary section of the explanatory note.

## 1. General Terms

**ВКР** — выпускная квалификационная работа.

**Пояснительная записка** — основной текстовый документ ВКР, содержащий описание предметной области, проектирования, реализации, тестирования и результатов работы.

**ООО «ЗСК»** — условная сетевая компания, используемая в работе как профильная организация для описания процесса обработки клиентских заявок и связанного документооборота.

**Клиентская заявка** — обращение клиента в сетевую компанию, содержащее данные заявителя, описание требуемого действия и сведения, необходимые для рассмотрения заявки сотрудником.

**Заявитель** — физическое лицо, от имени которого подается заявка. В текущей версии рассматривается заявитель-физическое лицо.

**Сотрудник** — пользователь системы со стороны сетевой компании, выполняющий проверку заявки, принятие решения и дальнейшее сопровождение документов.

**Документооборот** — совокупность действий, связанных с подготовкой, хранением, передачей и сопровождением документов, возникающих после рассмотрения клиентской заявки.

## 2. Web And Client-Server Terms

**Web-приложение** — программная система, доступная пользователю через web-браузер и взаимодействующая с серверной частью по сети.

**Клиент-серверная архитектура** — архитектурный подход, при котором пользовательский интерфейс и серверная бизнес-логика разделены между клиентской и серверной частями.

**Frontend** — клиентская часть web-приложения, отвечающая за отображение интерфейса, формы, маршрутизацию, взаимодействие пользователя с системой и отправку запросов к API.

**Backend** — серверная часть web-приложения, отвечающая за API, бизнес-логику, валидацию, авторизацию, обработку команд и работу с базой данных.

**SPA** (Single Page Application) — одностраничное web-приложение, в котором переходы между экранами выполняются без полной перезагрузки страницы.

**UI** (User Interface) — пользовательский интерфейс, то есть совокупность экранов, форм, кнопок, таблиц и других элементов взаимодействия пользователя с системой.

**UX** (User Experience) — опыт взаимодействия пользователя с системой, включающий удобство, понятность и предсказуемость работы интерфейса.

## 3. Technology Terms

**ASP.NET Core** — платформа для разработки серверных web-приложений и API на языке C#.

**C#** — объектно-ориентированный язык программирования, используемый для реализации серверной части приложения.

**React** — библиотека JavaScript для разработки пользовательских интерфейсов на основе компонентов.

**TypeScript** — язык программирования, расширяющий JavaScript статической типизацией.

**Entity Framework Core** — ORM-фреймворк для работы с реляционными базами данных из .NET-приложений.

**SQL Server** — реляционная система управления базами данных, используемая для хранения данных приложения.

**Vite** — инструмент сборки frontend-приложений, применяемый для разработки и сборки React/TypeScript-клиента.

## 4. API And Data Exchange Terms

**API** (Application Programming Interface) — программный интерфейс, через который frontend взаимодействует с backend.

**HTTP** (HyperText Transfer Protocol) — протокол прикладного уровня, используемый для обмена данными между клиентом и сервером.

**REST API** — стиль построения API, при котором клиент обращается к серверным ресурсам через HTTP-методы и URL-адреса.

**DTO** (Data Transfer Object) — объект передачи данных между слоями приложения или между клиентом и сервером.

**OpenAPI** — спецификация для описания структуры API, включая endpoint-ы, методы, схемы запросов, ответов и коды статусов.

**ProblemDetails** — стандартный формат описания ошибок HTTP API, используемый для передачи сведений об ошибках клиентской части.

**JSON** (JavaScript Object Notation) — текстовый формат обмена данными, используемый в API и генерируемых контрактных артефактах.

## 5. Architecture And Design Terms

**Доменная модель** — модель предметной области, включающая основные сущности, значения, состояния и правила поведения системы.

**Сущность** — объект предметной области, обладающий идентичностью и жизненным циклом, например клиентский аккаунт, заявитель или заявка.

**Значение** — объект, определяемый набором своих данных, например email, номер телефона или адрес.

**Инвариант** — правило, которое должно оставаться истинным при выполнении операций системы.

**Жизненный цикл заявки** — последовательность состояний заявки от создания и рассмотрения до одобрения или отклонения.

**Use Case** — вариант использования системы, описывающий взаимодействие актора с системой для достижения определенной цели.

**Актор** — пользователь или внешняя система, взаимодействующая с разрабатываемым приложением.

**Сценарий** — текстовое описание действий пользователя и системы, включающее предусловия, основной поток, альтернативные потоки и постусловия.

## 6. Testing Terms

**Модульное тестирование** — проверка отдельных классов, методов или доменных правил изолированно от внешней инфраструктуры.

**Интеграционное тестирование** — проверка взаимодействия нескольких компонентов системы, например API, обработчиков команд и базы данных.

**E2E-тестирование** (End-to-End) — проверка пользовательского сценария через реальный или приближенный к реальному пользовательский интерфейс и серверное взаимодействие.

**Тест-кейс** — описание проверяемого условия, входных данных, действий и ожидаемого результата.

**Валидация** — проверка входных данных на соответствие правилам системы.

## 7. Project-Specific Technical Terms

**L1-срез** — первый реализационный срез проекта, включающий базовые сценарии клиента и основу backend/API/frontend взаимодействия. В финальном тексте лучше использовать формулировку «первый функциональный срез», если термин L1 не объясняется отдельно.

**API-контракт** — согласованное описание взаимодействия между frontend и backend, включающее endpoint-ы, DTO, статусы ответов и формат ошибок.

**Семантические константы** — стабильные значения, значимые для клиента и сервера, например коды ошибок, имена полей и имена расширений ProblemDetails.

**Контрактные артефакты** — генерируемые файлы, фиксирующие API-структуру или семантические константы, например OpenAPI JSON, TypeScript-типы и JSON-файлы с кодами ошибок.
