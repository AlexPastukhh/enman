## Введение

Разработка информационных систем для автоматизации обработки клиентских обращений остаётся актуальной задачей для организаций, деятельность которых связана с регулярным приёмом заявок, проверкой данных и подготовкой сопроводительных документов. Для сетевой компании такие процессы имеют практическое значение, поскольку клиентская заявка обычно проходит несколько этапов: подачу данных, регистрацию обращения, рассмотрение сотрудником, принятие решения и дальнейшее оформление документов.

В рамках данной выпускной квалификационной работы рассматривается условная сетевая компания ООО «ЗСК». Предприятие используется как пример профильной организации, в которой требуется автоматизировать обработку клиентских заявок и сопровождение связанного с ними документооборота. Основное внимание в работе уделяется не особенностям конкретного юридического лица, а разработке программного решения, позволяющего централизовать действия клиента и сотрудника при работе с заявками.

Актуальность темы обусловлена тем, что ручная или разрозненная обработка клиентских заявок затрудняет контроль их состояния, увеличивает риск потери информации и усложняет подготовку документов после принятия решения. При отсутствии единой информационной системы сведения о клиенте, заявителе, заявке, результате рассмотрения и связанных документах могут храниться в разных источниках. Это приводит к дополнительным трудозатратам сотрудников, снижает прозрачность процесса для клиента и затрудняет последующий анализ обращений.

Разрабатываемое web-приложение должно обеспечить единый программный контур для базовых действий клиента и сотрудника. Клиент регистрируется в системе, выполняет вход, создаёт данные заявителя-физического лица и подаёт заявку. Сотрудник сетевой компании получает возможность работать с поступившими заявками, выполнять их проверку и принимать решение об одобрении или отклонении. После одобрения заявки система должна поддерживать дальнейшее создание проекта договора или сопроводительного документа, а также уведомление клиента о результате обработки.

Целью выпускной квалификационной работы является разработка web-приложения для автоматизации ведения документооборота и обработки клиентских заявок в сетевой компании ООО «ЗСК».

Для достижения поставленной цели необходимо решить следующие задачи:

```text
1. Проанализировать предметную область обработки клиентских заявок в сетевой компании.
2. Выявить проблемы ручной или разрозненной обработки заявок и документов.
3. Проанализировать существующие подходы и альтернативные решения.
4. Определить роли пользователей и основные пользовательские сценарии.
5. Сформировать функциональную спецификацию поведения системы.
6. Спроектировать архитектуру web-приложения.
7. Спроектировать доменную модель заявителя, заявки и связанных процессов.
8. Спроектировать структуру хранения данных.
9. Реализовать серверную часть приложения на ASP.NET Core.
10. Реализовать клиентскую часть приложения на React и TypeScript.
11. Организовать согласование серверной и клиентской частей через API-контракт.
12. Выполнить тестирование реализованных модулей.
13. Определить ограничения текущей версии и направления дальнейшего развития.
```

Объектом исследования является процесс обработки клиентских заявок и связанных с ними документов в сетевой компании.

Предметом исследования является web-приложение, предназначенное для автоматизации подачи, рассмотрения и сопровождения клиентских заявок.

Практическая значимость работы заключается в том, что разработанное приложение может использоваться как основа для единой системы обработки заявок. Такая система позволяет уменьшить количество разрозненных действий, повысить прозрачность состояния заявки, упростить контроль связей между клиентским аккаунтом, заявителем, заявкой и документами, а также подготовить основу для дальнейшего расширения документооборота.

В качестве технологической основы используются ASP.NET Core для серверной части, React и TypeScript для клиентской части, Entity Framework Core для доступа к данным и SQL Server для хранения информации. Для согласования backend и frontend применяется контрактный подход: структура API фиксируется через OpenAPI, а клиентские семантические константы выносятся в отдельные генерируемые артефакты. Такой подход снижает риск рассинхронизации между серверной и клиентской частями приложения.

В первой части работы рассматривается предметная область, особенности обработки клиентских заявок, проблемы существующего процесса и обоснование необходимости автоматизации. Во второй части описываются требования, пользовательские сценарии, архитектура приложения, доменная модель, структура данных и проектные решения. В третьей части приводится описание реализации web-приложения, серверной и клиентской частей, API-контракта, пользовательского интерфейса и тестирования. В заключении формулируются результаты работы, ограничения текущей версии и направления дальнейшего развития системы.
