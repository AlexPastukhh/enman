# Clean Architecture

Status: draft

## Архитектурный стиль

Система реализуется как web-приложение с клиент-серверной архитектурой. Пользователь взаимодействует с frontend-частью через браузер. Frontend обращается к backend API. Backend выполняет бизнес-операции и сохраняет данные в базе данных.

## Backend

Backend построен на ASP.NET Core. Он отвечает за:

- прием HTTP-запросов;
- выполнение бизнес-операций;
- валидацию входных данных;
- аутентификацию и авторизацию;
- взаимодействие с базой данных;
- формирование ответов API;
- подготовку основы для уведомлений.

## Frontend

Frontend строится на React и TypeScript. Он отвечает за:

- страницы регистрации и входа;
- формы создания заявителя и заявки;
- личный кабинет клиента;
- рабочее место сотрудника;
- отображение статусов заявок;
- отображение документов и договорных предложений.

## Доменный слой

Доменный слой содержит основные сущности предметной области: клиентский аккаунт, заявитель, заявка, а в полной версии — результат проверки, документ и уведомление.

## Слой приложения

Слой приложения реализует команды и обработчики. Такой подход отделяет сценарии использования от контроллеров и упрощает тестирование.

## Слой хранения данных

Для хранения данных используется Entity Framework Core и SQL Server. Сущности L1 отображаются на таблицы базы данных. В дальнейшем модель хранения может быть расширена таблицами сотрудников, результатов проверки, документов и уведомлений.

## Внешние интеграции

Email-уведомления должны быть вынесены в отдельный сервис уведомлений. Это позволит заменить способ отправки писем без изменения доменной логики обработки заявки.
